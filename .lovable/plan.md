# خطة بناء النظام

## نظرة عامة على المعمارية

سنقسم النظام على جزئين يشتغلون مع بعض:

```text
┌─────────────────────┐         ┌──────────────────────┐
│   VPS (Python)      │◄───────►│  Lovable Cloud (DB)  │
│  - Telegram Bot     │  يحفظ   │  - Postgres          │
│  - Facebook Scraper │  يقرأ   │  - Auth              │
│  - Apify Runner     │         └──────────┬───────────┘
└─────────────────────┘                    │
                                           │
                              ┌────────────▼──────────┐
                              │  واجهة ويب (Lovable)   │
                              │  - Dashboard          │
                              │  - إدارة المفاتيح      │
                              │  - عرض الأرقام         │
                              └───────────────────────┘
```

**السبب:** الـ VPS يشغل السكربت الحالي (Python + Apify) بدون قيود وقت التنفيذ. Lovable يعطيك واجهة احترافية + قاعدة بيانات مشتركة + نظام دخول آمن. الاثنين يتكلمون عبر REST API.

## المرحلة 1: قاعدة البيانات + المصادقة (Lovable Cloud)

جداول:

- `searches` — كل عملية بحث (كلمة مفتاحية، دولة، حالة، تاريخ)
- `extracted_numbers` — الأرقام المستخرجة (رقم، رابط الصفحة، search_id، حالة الإرسال)
- `apify_keys` — مفاتيح Apify (المفتاح، حالة، عداد الاستخدام، آخر خطأ)
- `sent_numbers` — الأرقام المرسلة سابقاً (لتجنب التكرار)
- `bot_settings` — إعدادات (Telegram user ID المسموح، إلخ)

دخول ببريد وكلمة سر — حساب واحد لك فقط. RLS مفعل.

## المرحلة 2: واجهة الويب (Lovable)

**Dashboard رئيسي:**

- إحصائيات: عدد الأرقام اليوم/الأسبوع، عدد المفاتيح النشطة، آخر عمليات البحث
- زر "بحث جديد" (يرسل أمر للبوت عبر API)

**صفحة نتائج البحث:**

- جدول بكل الأرقام مع فلترة (بحث، دولة، تاريخ)
- تصدير CSV / TXT
- نسخ جماعي، تعليم كـ "مُرسل"

**صفحة المفاتيح:**

- قائمة مفاتيح Apify مع الحالة (نشط/منتهي)
- إضافة مفتاح جديد
- حذف / تعطيل
- عرض عداد الاستخدام لكل مفتاح

**صفحة السجل:**

- كل عملية بحث سابقة مع النتائج

**صفحة الإعدادات:**

- Telegram User ID المسموح له استخدام البوت
- تحميل ملف `sent_numbers.txt`

التصميم: لوحة تحكم عصرية داكنة، RTL عربي، Tailwind.

## المرحلة 3: API endpoints (Lovable — `/api/public/*`)

نقاط اتصال محمية بتوكن سري يعرفه بوت VPS:

- `POST /api/public/bot/search` — إنشاء عملية بحث جديدة
- `GET /api/public/bot/keys` — جلب المفاتيح النشطة
- `POST /api/public/bot/keys/mark-exhausted` — تعليم مفتاح كمنتهي
- `POST /api/public/bot/numbers` — رفع أرقام مستخرجة
- `POST /api/public/bot/keys/add` — إضافة مفتاح جديد (البوت يستدعيها لما ترسل مفتاح جديد للبوت)

## المرحلة 4: بوت تلجرام + سكربت VPS (Python)

نبني على السكربت الحالي ونضيف:

**أوامر البوت:**

- `/search` — يسأل الكلمة المفتاحية ثم الدولة (قائمة أزرار) ثم يبدأ
- `/addkey <apify_key>` — إضافة مفتاح جديد
- `/keys` — عرض حالة المفاتيح
- `/stats` — إحصائيات سريعة
- `/cancel` — إلغاء عملية جارية

**تدفق البحث الكامل:**

1. المستخدم يرسل كلمة + دولة
2. البوت يفتح مكتبة إعلانات فيسبوك عبر Apify Actor (Facebook Ads Library Scraper)
3. يستخرج روابط الصفحات النشطة
4. يشغل سكربتك الحالي لاستخراج أرقام واتساب
5. يصفي الأرقام المكررة (يقارن مع `sent_numbers`)
6. يحفظ كل شي في Lovable Cloud عبر API
7. يرسل الأرقام النظيفة للمستخدم كملف + رسالة

**إدارة المفاتيح الذكية:**

- يقرأ المفاتيح من Lovable Cloud (مو من الكود)
- لما مفتاح ينتهي (خطأ 402/429): يعلمه كـ exhausted تلقائياً وينتقل للتالي
- لما ترسل `/addkey`: يضاف فوراً للـ pool

**تشغيل على VPS:**

- `systemd service` لتشغيل البوت 24/7
- دليل تنصيب مفصل (git clone, venv, .env, systemctl)

## القسم التقني

### Stack

- **Frontend:** TanStack Start + React + Tailwind + shadcn/ui (RTL)
- **Backend Lovable:** Server functions + `/api/public/*` للبوت
- **DB:** Lovable Cloud (Postgres + Auth + RLS)
- **VPS:** Python 3.11 + `python-telegram-bot` + `apify-client` + `requests`

### الأمان

- توكن سري (`BOT_API_TOKEN`) بين VPS و Lovable — يتحقق منه في كل `/api/public/bot/*`
- Telegram user ID whitelist في البوت (بس أنت)
- مفاتيح Apify مشفرة في DB
- RLS على كل الجداول

### الترتيب

1. تفعيل Lovable Cloud + جداول + auth
2. بناء الواجهة (dashboard, keys, numbers, history, settings)
3. بناء `/api/public/bot/*` endpoints
4. كتابة كود Python للبوت + تعديل سكربتك ليقرأ المفاتيح من API
5. توفير دليل تنصيب VPS (systemd unit + .env template)

## ما تحصل عليه في النهاية

- رابط ويب تفتحه من أي مكان لإدارة كل شي
- بوت تلجرام يشتغل 24/7 على VPS
- سكربت Python جاهز مع ملفات تنصيب VPS
- كل الأرقام محفوظة ومنظمة ومصنفة
- إضافة مفاتيح Apify من التلجرام مباشرة

**ملاحظة:** Apify متوفر كموصل جاهز في Lovable، لكن بما أن السكربت راح يشتغل على VPS، راح نستخدم مفاتيحك مباشرة عشان تتحكم فيها من واجهتك.

هل أبدأ التنفيذ بهذه الخطة؟  بصراحة الخطة قوية جدًا، وهي أقرب لبناء منتج حقيقي وليس مجرد سكربت. والأهم أنها تتوافق مع هدفك الأساسي: نظام يعتمد عليه ويكبر مع الوقت، بدل أن تضطر لإعادة كتابته كل شهر.

لكن عندي بعض التعديلات التي أعتقد أنها ستجعلها أفضل وأكثر قابلية للتوسع.

2. بناء الـ API.
3. تطوير الـ Worker على الـ VPS وربطه بالـ API.
4. اختبار دورة العمل كاملة (بحث → استخراج → حفظ → إرسال).
5. بعد التأكد أن المنطق يعمل، أنشئ لوحة التحكم فوقه.

بهذه الطريقة لن تضطر إلى تعديل الواجهة كلما تغيرت بنية النظام، وسيكون التطوير أسرع وأكثر استقرارًا.
